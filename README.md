# Maktaba — نظام إدارة المكتبات والطباعة

> **تحديث 0.2.0:** تم إصلاح migrations الأساسية، إضافة شاشة تسجيل الدخول/الخروج، ربط المشتريات والخزينة بالـ API، تصحيح تكلفة القطعة، فحص المخزون داخل المعاملة، عمود `type` لحركات المخزون، حماية XSS في الطباعة، وValidationPipe وCORS قابلين للتهيئة.

نسخة تطويرية لنظام متعدد المكتبات (multi-tenant) بواجهة عربية RTL، وواجهة React + TypeScript، وخادم NestJS، وقاعدة PostgreSQL باستخدام Prisma، وتخزين محلي IndexedDB/Dexie.

> **تنبيه:** هذه نسخة تطوير وليست جاهزة للنشر التجاري أو لتسجيل معاملات حقيقية. تمت إضافة مصادقة JWT وواجهات API للمشتريات في هذه المرحلة، لكن شاشة المشتريات في الواجهة ما زالت تحفظ محليًا في IndexedDB ولا تتزامن تلقائيًا مع API. لم يتم بعد تنفيذ المخزون الفعلي أو اختبارات الأمان والضغط أو مزامنة offline-first.


## تشغيل سريع على Windows

1. ثبّت [Node.js 20+](https://nodejs.org) و [PostgreSQL](https://www.postgresql.org/download/windows/).
2. أنشئ قاعدة مرة واحدة من pgAdmin أو psql:
   ```sql
   CREATE DATABASE library_erp;
   ```
3. عدّل `apps/api/.env` إن لزم (خصوصًا كلمة مرور postgres):
   ```env
   DATABASE_URL="postgresql://postgres:YOUR_PASSWORD@localhost:5432/library_erp?schema=public"
   ```
4. من مجلد المشروع اضغط مرتين على **`start.bat`**.
   - يثبت الحزم عند الحاجة
   - يحدّث جداول قاعدة البيانات
   - يشغّل الخادم والواجهة ويفتح المتصفح

للإيقاف: أغلق نافذتي `Maktaba API` و `Maktaba Web` أو شغّل `STOP.bat`.

## التشغيل على Windows / PowerShell

### 1. تشغيل PostgreSQL
من مجلد المشروع:

```powershell
docker compose up -d db
```

### 2. إعداد الخادم

```powershell
Copy-Item apps/api/.env.example apps/api/.env
```

افتح `apps/api/.env`، وغيّر `JWT_SECRET` إلى قيمة عشوائية طويلة وفريدة قبل أي استخدام خارج جهاز التطوير، واضبط كلمة مرور قاعدة البيانات لتطابق `docker-compose.yml`.

ثم:

```powershell
cd apps/api
npm install
npm run prisma:generate
npm run prisma:validate
npm run prisma:migrate:dev -- --name init
npm run start:dev
```

الخادم: `http://localhost:3000`، وفحص الصحة: `http://localhost:3000/api/health`.

### 3. تشغيل الواجهة
في نافذة PowerShell ثانية من جذر المشروع:

```powershell
cd apps/web
npm install
npm run dev
```

افتح العنوان الذي يظهر في الطرفية، غالبًا `http://localhost:5173`.

## واجهات API المتاحة
كل المسارات مسبوقة بـ `/api`.

### التسجيل وتسجيل الدخول
- `POST /auth/register` لإنشاء مكتبة وحساب مالك في عملية واحدة.
- `POST /auth/login` لتسجيل الدخول.

مثال التسجيل:

```json
{
  "organizationName": "مكتبتي",
  "slug": "my-library",
  "phone": "01000000000",
  "fullName": "اسم صاحب المكتبة",
  "email": "owner@example.com",
  "password": "ضع-كلمة-مرور-طويلة-هنا"
}
```

كلمة المرور يجب ألا تقل عن 10 أحرف، وتُخزّن كقيمة hash باستخدام bcrypt. يعيد الخادم `accessToken` صالحًا لمدة 8 ساعات. أرسل الرمز مع طلبات API المحمية في الترويسة:

```text
Authorization: Bearer <accessToken>
```

### الموردون وفواتير الوارد
- `GET /suppliers` — قائمة موردي المكتبة المسجل دخولها.
- `POST /suppliers` — إضافة/تحديث مورد بالاسم داخل المكتبة.
- `GET /purchases/invoices` — فواتير المكتبة.
- `POST /purchases/invoices` — إنشاء فاتورة مع الأصناف والخصم والمدفوع.
- `GET /suppliers/payments` و`POST /suppliers/payments` — عرض دفعات الموردين وتسجيل دفعة.
- `GET /purchases/returns` و`POST /purchases/returns` — عرض مرتجعات المشتريات وتسجيل مرتجع على فاتورة.

جميع هذه المسارات تتطلب رمز دخول. يحدد الخادم `organizationId` من الرمز ولا يأخذه من جسم الطلب، ويقيّد الاستعلامات بالمكتبة المسجّلة دخولها.

## ما أُنجز
- واجهة React + TypeScript عربية RTL وPWA.
- تخزين محلي عبر Dexie/IndexedDB وشاشة فواتير وارد ومقارنة أسعار محلية.
- مخطط Prisma للمكتبات والفروع والمستخدمين والموردين والأصناف وفواتير الوارد وبنودها والمدفوعات والمرتجعات.
- تسجيل حساب مالك مع إنشاء المكتبة، وتسجيل دخول باستخدام JWT وكلمات مرور مشفّرة بـ bcrypt.
- API للموردين وفواتير الوارد ودفعات الموردين ومرتجعات المشتريات.
- قصر بيانات API على المكتبة الموجودة في رمز الدخول.

## ما تبقّى قبل الإنتاج
1. ربط شاشة المشتريات في React بواجهات API، مع طابور مزامنة offline موثوق ومعالجة التعارضات.
2. إدارة المستخدمين والأدوار والصلاحيات، وتجديد/إنهاء الجلسات، وتحديد معدل محاولات تسجيل الدخول.
3. تنفيذ دفتر مخزون وحركات مخزون؛ المرتجع الحالي يسجل الأثر المالي ولا يحدّث مخزونًا بعد.
4. اختبارات آلية للـ API، ومعالجة حالات التزامن المتزامن في المرتجعات، وسجل تدقيق.
5. إعدادات نشر HTTPS، ونسخ احتياطي واستعادة مجرّبة، ومراجعة أمنية قبل الاستخدام التجاري.

## أمان
- لا ترفع ملفات `.env` أو كلمات المرور أو رموز الدخول إلى GitHub.
- لا تستخدم `JWT_SECRET` الافتراضي في بيئة الإنتاج.
- لا تعرض PostgreSQL مباشرة على الإنترنت.
- لا تعتبر التخزين المحلي بديلًا عن النسخ الاحتياطي.

## المرحلة الرابعة: أساسيات المخزون

أضيفت واجهة أولية للمخزون في `apps/web/src/ui/Inventory.tsx` ومسارات محمية:
- `GET /api/inventory` لعرض رصيد أصناف المكتبة الحالية.
- `POST /api/inventory/adjustments` لتسجيل تسوية جرد بكمية موجبة أو سالبة وسبب واضح.
- نموذج `StockMovement` لتسجيل تسويات الجرد في PostgreSQL مع ربطها بالمكتبة والصنف.

يُحسب الرصيد بوحدات القطعة الأساسية: كميات الوارد تُحوّل من العبوات إلى قطع باستخدام `piecesPerPack`، ثم تُخصم المرتجعات وتُضاف التسويات. يتطلب ذلك تطبيق migration جديد بعد تحديث المخطط:

```powershell
cd apps/api
npm run prisma:generate
npm run prisma:validate
npm run prisma:migrate:dev -- --name inventory_movements
```

**حدود هذه المرحلة:** شاشة فواتير الوارد الحالية لا تزال تحفظ محليًا في IndexedDB ولا تُرسل فواتيرها إلى الخادم، ولذلك لن تظهر تلك الفواتير في رصيد المخزون السحابي. كما أن وحدات البيع والمبيعات والتقارير والمزامنة offline-first لا تزال غير مكتملة. لا تستخدم هذه النسخة لإدارة مخزون فعلي قبل ربط الوارد واختبار عمليات الشراء والمرتجعات والتسويات.


## المرحلة الخامسة: نقطة البيع

أُضيفت شاشة مبيعات أولية إلى الواجهة ومسارات محمية في الخادم:
- `GET /api/sales` لعرض أحدث فواتير البيع.
- `POST /api/sales` لإنشاء فاتورة بيع مع الأصناف والخصم والمدفوع.
- يتحقق الخادم من أن الأصناف تتبع المكتبة، ويمنع البيع إذا كان الرصيد المحسوب غير كافٍ.
- تُسجّل حركة مخزون سالبة لكل فاتورة بيع داخل معاملة قاعدة بيانات، وتُعرض كمية المباع منفصلة عن تسويات الجرد.
- تعرض الشاشة سجل الفواتير وإجمالي المبيعات والمبالغ المتبقية.

بعد تحديث المخطط، شغّل migration جديدًا من `apps/api`:

```powershell
npm run prisma:generate
npm run prisma:validate
npm run prisma:migrate:dev -- --name sales
npm run build
```

ثم اختبر إنشاء فاتورة، والتأكد من انخفاض المخزون، ورفض البيع بكمية أكبر من المتاح.

**حدود مهمة:** هذه شاشة بيع أولية؛ لا توجد طباعة إيصال، أو مرتجعات بيع، أو إدارة عملاء ومديونيات كاملة، أو إعداد سعر بيع من شاشة الأصناف. فحص الرصيد قبل إنشاء الفاتورة لا يمنع وحده سباق الطلبات المتزامنة من جهازين، لذا يجب إضافة قفل/تحديث ذري للمخزون واختبارات تزامن قبل الاستخدام التجاري. كما أن الشاشة تتطلب اتصالًا بالخادم حاليًا ولا تعمل للبيع دون إنترنت.


## المرحلة السادسة: خدمات الطباعة والتصوير

أضيفت شاشة خدمات الطباعة والتصوير إلى الواجهة، وتشمل إيصالات للتصوير والطباعة والسكانر والتغليف والتجليد، حساب السعر والخصم والمدفوع والمتبقي، سجل بحث وإعادة طباعة الإيصالات، وإعداد أسعار الخدمات. بيانات هذه الوحدة محفوظة محليًا في IndexedDB/Dexie وتعمل دون اتصال على الجهاز الحالي؛ لم تُربط بعد بقاعدة PostgreSQL أو الخزينة المشتركة.


## المرحلة السابعة: دفتر الخزينة والمصروفات (محلي)

أضيفت شاشة `الخزينة والحسابات` في الواجهة، وتتضمن تسجيل الإيرادات والمصروفات، تصنيف الحركة، التاريخ وطريقة الدفع والمرجع والملاحظات، ملخص الفترة، الرصيد التراكمي للحركات المسجلة، البحث والتصفية حسب التاريخ، وتصدير CSV. أضيف جدول `cashTransactions` إلى Dexie عبر الإصدار الرابع، مع ترحيل تلقائي لقاعدة IndexedDB الحالية عند فتحها.

**حدود مهمة:** هذه الشاشة دفتر نقدية محلي مستقل، وليست دفتر أستاذ محاسبيًا كاملًا. لا تجمع تلقائيًا المقبوضات من المبيعات والطباعة أو المدفوعات للموردين؛ يجب عدم تكرار تسجيل الحركة نفسها. لا توجد مزامنة أو عزل بيانات بين الأجهزة لهذه الوحدة حتى الآن. لا تعتمد على صافي الحركة بوصفه ربحًا؛ حساب الربح يتطلب تكلفة البضاعة والمصروفات والمخزون والقيود المحاسبية.

## المرحلة الثامنة: تأسيس الخزينة المشتركة عبر API وPostgreSQL

أضيف جدول `CashTransaction` في Prisma ومهاجرة PostgreSQL، مع واجهات محمية بتسجيل الدخول:

- `GET /accounting/cash-transactions` — عرض الحركات، ويدعم `from` و`to` و`kind` و`search` كمعاملات اختيارية.
- `GET /accounting/cash-transactions/summary` — إجمالي الإيرادات والمصروفات وصافي الحركة وعدد الحركات، مع فلاتر التاريخ الاختيارية.
- `GET /accounting/cash-transactions/:id` — عرض حركة واحدة ضمن مكتبة المستخدم.
- `POST /accounting/cash-transactions` — إضافة حركة يدوية. الحقول: `kind` بقيمة `INCOME` أو `EXPENSE`، و`category`، و`amount` أكبر من صفر، واختياريًا `date` و`method` (`CASH` أو `WALLET` أو `BANK` أو `CARD`) و`reference` و`notes`.
- `DELETE /accounting/cash-transactions/:id` — حذف حركة من مكتبة المستخدم.

كل استدعاء يتطلب `Authorization: Bearer <token>`، وتُحدد المكتبة من رمز الدخول وليس من جسم الطلب، لمنع الوصول إلى حركات مكتبة أخرى. تُرسل المبالغ بصيغة Decimal في قاعدة البيانات. لتطبيق المخطط على قاعدة جديدة/قائمة بعد تجهيز البيئة، شغّل من مجلد `apps/api`:

```bash
npm run prisma:generate
npm run prisma:migrate:deploy
npm run build
```

**تنبيه تكاملي:** هذه المرحلة تنشئ التخزين المركزي وواجهات API فقط؛ شاشة الخزينة الحالية في الويب ما زالت تستخدم IndexedDB محليًا ولم تُحوّل بعد لاستهلاك هذه الواجهات. كذلك لم يتم حتى الآن إنشاء قيود تلقائية من المبيعات أو الطباعة أو دفعات الموردين؛ تركنا ذلك منفصلًا عمدًا حتى تُصمم آلية منع التكرار وربط المصدر المالي بشكل آمن. لم يُنفذ build أو اختبار اتصال فعلي بقاعدة PostgreSQL في بيئة العمل هذه.
